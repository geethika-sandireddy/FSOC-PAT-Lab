# Technical Report: AI-Based Virtual Camera Tracking System for Coarse Alignment of Mobile FSOC Terminals

**Problem Statement ID: 26169 — ISRO SIH 2026**

---

## 1. Problem Statement and Motivation

Free-Space Optical Communication (FSOC) offers dramatically higher data rates than RF links for satellite, aerial, and ground-to-ground communications. However, FSOC terminals require precise beam-pointing: even sub-degree boresight errors cause signal loss over tens of kilometers. When the FSOC terminal is mounted on a mobile platform — a ship, vehicle, or UAV — platform motion, vibrations, atmospheric turbulence, and relative orbital dynamics all introduce pointing disturbances that the acquisition and tracking system must reject in real time.

ISRO's Problem Statement 26169 asks for "Development of an AI-Based Virtual Camera Tracking System for Coarse Alignment of Mobile FSOC Terminals." The core challenge is to build an autonomous system that can:

1. **Detect** the remote FSOC beacon in a cluttered FOV containing distractors and obstacles.
2. **Identify** the true beacon using its unique 15 Hz amplitude-modulation signature.
3. **Track** the beacon continuously despite atmospheric scintillation, platform vibrations, and line-of-sight occlusions.
4. **Steer** a two-axis gimbal to maintain sub-degree boresight alignment in closed loop.

Our solution is a complete real-time simulation and control pipeline running at 30–48 fps on commodity hardware with no GPU acceleration, implemented in pure Python with pygame-ce, OpenCV, and NumPy.

## 2. System Architecture

### 2.1 Pipeline Overview

The system follows a classic sense-process-act loop:

```
Scene Rendering → Sensor Model → Detection → Classification → Tracking → Estimation → Gimbal Control
```

Each frame (~16–33 ms at 30–60 fps), the following steps execute sequentially:

1. **Scene rendering** (`core/scene.py`, `core/sensor.py`): The relative orbital model computes the beacon's angular position; the sensor model renders a Gaussian PSF onto an 800×450 pixel focal-plane array with the beacon's 15 Hz square-wave intensity modulation applied.

2. **Disturbance injection** (`core/disturbances.py`): Atmospheric turbulence (Kolmogorov-approximation via random phase screens), platform vibrations, sensor noise, and random platform jerks corrupt the image.

3. **Detection** (`core/detection.py`): OpenCV blob detection identifies bright point sources; a logistic-regression ML classifier scores each candidate on appearance features (SNR, area, circularity, centroid position).

4. **Classification** (`ai/classifier.py`): The ML model outputs a classification score (0–1) for each candidate, distinguishing beacon-like objects from distractors.

5. **Tracking** (`core/tracking.py`): A finite-state machine (SEARCHING → TENTATIVE → LOCKED → COASTING) manages acquisition. While LOCKED, modulation correlation and suspect-floor monitoring validate the tracked object's identity.

6. **Estimation** (`core/tracking.py`): The boresight estimate is computed as an ephemeris prior plus a leaky-absorbed bias term, providing smooth, low-latency commands.

7. **Gimbal control** (`core/gimbal.py`, `core/control.py`): A PD position controller with slew-rate limiting and acceleration clamping drives the two-axis gimbal to follow the estimated boresight, with a 2-frame latency FIFO modeling pipeline delay.

### 2.2 Configuration Centralization

All tunable parameters are centralized in `config.py`, including camera optics (HFOV = 2.4°, focal length ≈ 19,099 px), modulation parameters (15 Hz, ±50% depth), servo gains (Kp = 25, Kd = 10), and five difficulty presets (EASY through ADVERSARIAL). This allows rapid parameter sweeps and A/B testing without code changes.

## 3. Scene and Sensor Model

### 3.1 Relative Orbital Dynamics

The beacon's angular trajectory is generated by `RelativeOrbitModel` (`core/scene.py`), which produces a Lissajous-like pattern in azimuth and elevation with configurable amplitude (1.0°–2.6°), frequency ratio, and speed multiplier. A random platform-jerk model adds occasional step disturbances (0–9% probability per frame) that simulate sudden platform motions.

### 3.2 Gaussian PSF Rendering

The beacon is rendered as a 2D Gaussian point-spread function:

```
I(x, y) = A · exp(-((x-μx)² + (y-μy)²) / (2σ²))
```

where σ is tuned to produce a 3–7 pixel radius core matching typical FSOC telescope optics. Sub-pixel centering is achieved using numpy's `np.rint` with `np.add.at` for accumulator-based rendering, eliminating the systematic 0.036° measurement bias present in earlier bilinear-interpolation approaches.

### 3.3 Intensity Modulation

The beacon alternates between a "bright" state (peak ≈ 252 DN) and a "dim" state (peak ≈ 118 DN) at 15 Hz (30 Hz modulation frequency with 50% duty cycle). This square-wave signature is the primary discriminant against distractors, which operate at 0 Hz (steady), 3 Hz, or 8 Hz modulation frequencies.

### 3.4 Distractors and Obstacles

- **Distractors** (`Distractor` class): Bright point sources with non-beacon modulation frequencies. At higher difficulty levels, distractors are placed on orbits that periodically overlap the beacon's trajectory, creating blended-blob ambiguity.
- **Obstacles** (`Obstacle` class): Opaque circular disks that periodically occlude the beacon, testing the tracker's coast-and-reacquire capability.

## 4. Disturbance Engine

The disturbance engine (`core/disturbances.py`) models four independent degradation sources, all operating in real time:

### 4.1 Atmospheric Turbulence

A Kolmogorov-approximation turbulence model generates random velocity fields that warp the focal-plane image. For efficiency, the warp field is computed at 4× downsample resolution (200×112 instead of 800×450) and resized to full resolution using bilinear interpolation, reducing computation by ~16× while preserving the correct spatial statistics.

Turbulence strength is parameterized from 5 (negligible) to 85 (extreme scintillation), affecting both image distortion and intensity fluctuations.

### 4.2 Platform Vibration

High-frequency sinusoidal vibrations with random phase offsets simulate platform structural vibrations. Vibration amplitude scales from 2 (smooth platform) to 45 (rough maritime environment).

### 4.3 Sensor Noise

Additive Gaussian sensor noise with zero mean and configurable standard deviation (5–38 DN) models thermal noise, read noise, and quantization. The noise is computed in-place using reusable float32 scratch buffers with `numpy.random.standard_normal`, avoiding per-frame memory allocation.

### 4.4 Sky Background

A subtle radial-gradient sky background provides realistic non-uniform illumination, testing the detection pipeline's ability to handle spatially varying noise floors.

### 4.5 Performance Optimization

The disturbance engine's total per-frame cost is approximately 2–5 ms at typical settings, achieved through:
- 4× warp-field downsampling with bilinear resize
- Reusable noise buffers (no per-frame allocation)
- In-place operations throughout

## 5. Detection and ML Classification

### 5.1 Blob Detection

OpenCV's `SimpleBlobDetector` identifies bright point sources above an adaptive threshold (`DETECTION_ABS_THRESHOLD = 42 DN`). For each detected blob, the system computes:

- **Centroid** (u, v) via intensity-weighted moments
- **Peak intensity** (maximum pixel value in the blob)
- **SNR** (signal-to-noise ratio relative to local background)
- **Area** (number of pixels above threshold, normalized)
- **Circularity** (4π·area / perimeter²)

### 5.2 Logistic-Regression Classifier

A binary logistic-regression model (`ai/classifier.py`) scores each candidate on a 5-dimensional feature vector:

```
features = [area_norm, snr, circularity, hue_dist_n, peak_normalized]
```

The classifier was trained on 10,000 synthetic examples (5,000 beacon, 5,000 distractor) with Gaussian augmentation for noise robustness. Training achieves 96.2% train accuracy and 97.0% validation accuracy. The weights are baked into the source code (`ai/classifier.py`) to eliminate runtime dependency on training infrastructure.

The classification threshold (`ML_LOCK_THRESHOLD = 0.40`) is deliberately low to maximize recall (avoid missing the true beacon) at the cost of some false positives, which are filtered downstream by modulation correlation and spatial consistency.

## 6. Tracking State Machine

The tracking system (`core/tracking.py`) implements a four-state finite-state machine with well-defined transitions:

### 6.1 SEARCHING

No track exists. The system scans all candidates that pass the ML appearance gate and fall within the ephemeris prior gate (radius growing from 0.55° to 2.2° as a function of time since last candidate). The best candidate by fusion score (ML × prior geometric agreement) initiates a tentative track.

### 6.2 TENTATIVE

A spatial-consistency filter requires the candidate to remain within 0.12° (3 pixels) of its initial position for 3 consecutive frames. This rejects transient noise spikes and ensures the candidate is a genuine, stable object. The modulation correlator accumulates the candidate's brightness history during this phase.

### 6.3 LOCKED

Once both spatial consistency (3 frames) AND modulation correlation ≥ 0.62 are satisfied, the tracker commits to LOCKED. While locked:

- **Association**: Each frame, the candidate nearest to the current boresight estimate (within 0.30°) is associated.
- **Modulation verification**: A suspect-floor monitor checks that the correlation stays ≥ 0.58 for up to 30 consecutive frames. If it drops below, the tracker assumes a wrong-target lock and reverts to SEARCHING.
- **Estimation update**: The bias filter absorbs the measured boresight error with α = 0.35, providing exponential smoothing.

### 6.4 COASTING

If no candidate is detected (e.g., during obstacle occlusion), the tracker enters COASTING mode, extrapolating the boresight from the orbital prior while holding the bias constant. COASTING is time-limited (0.45 s); if no re-detection occurs, the tracker reverts to SEARCHING.

## 7. Phase-Robust Modulation Correlator

### 7.1 The Problem

The beacon's 15 Hz amplitude modulation produces a square-wave intensity pattern at the sensor. To identify the beacon, the system correlates the observed brightness history against a template representing the expected modulation pattern.

A naive implementation anchors the template at a fixed frame offset (e.g., `frame_n - 1` to account for pipeline latency). However, the exact latency varies with seed, platform state, and rendering pipeline timing. When the template phase misaligns by even half a cycle, the correlation collapses from ~0.95 to ~0.50 (random agreement), causing the tracker to lose the beacon.

### 7.2 The Solution: Max-Over-Lags

The phase-robust correlator tests three lag hypotheses simultaneously:

```
for lag in (0, 1, 2):
    corr_lag = sign_agreement(brightness, template(frame_n - lag))
return max(corr_0, corr_1, corr_2)
```

Since the true pipeline latency is approximately 1 frame (PSF rendering + sensor readout), one of the three lags always aligns with the true modulation phase. This raises the minimum correlation for the true beacon from ~0.50 (pre-fix) to ≥0.78 (post-fix) across all presets, while decoy correlations remain ≤0.56.

### 7.3 Correlation Metric

The correlation is computed as:

```
agree = Σ sign(v_i - mean(v)) × sign(template(frame_i - lag))
corr = (agree/n + 1) / 2     ∈ [0, 1]
```

where `sign(v_i - mean(v))` classifies each sample as "bright" (+1) or "dim" (-1), and the template sign is deterministic based on the absolute frame index and the modulation frequency.

## 8. Gimbal Control System

### 8.1 PD Position Controller

The gimbal servo (`core/gimbal.py`) implements a damped PD (proportional-derivative) position controller:

```
command = Kp × (target - current) + Kd × (0 - velocity)
```

with Kp = 25.0 and Kd = 10.0. The derivative term acts on zero velocity (setpoint regulation), providing damping to prevent overshoot.

### 8.2 Slew-Rate and Acceleration Limiting

Physical gimbal constraints are enforced:
- **Maximum slew rate**: 10°/s (configurable)
- **Acceleration limit**: 14°/s² (configurable)

These limits prevent unrealistic instantaneous velocity changes and model the inertia of a real two-axis gimbal.

### 8.3 Pipeline Latency Model

A timestamp-based latency FIFO models the 2-frame pipeline delay between command issuance and gimbal response. Commands are pushed as `(frame_index, pan, tilt)` tuples and popped exactly `GIMBAL_LATENCY_FRAMES` frames later, ensuring the control loop sees the correct delayed response.

### 8.4 Independent Axis Control

Azimuth and elevation axes are controlled independently, each with its own PD controller, slew limiter, and latency FIFO. The `GimbalState` dataclass tracks realized pose, commanded pose, velocities, and timestamps.

## 9. Performance Results

### 9.1 Benchmark Methodology

All results are obtained using the headless stress-test harness (`metrics/stress_test.py`) running 3 independent trials of 15 seconds each (900 frames per trial at 60 fps), with different random seeds per trial. Metrics are reported as means across trials.

### 9.2 Quantitative Results

| Preset | Acquisition Time | Retention (%) | Mean Error (°) | RMS Error (°) | Max Error (°) | False Locks | FPS |
|--------|-----------------|---------------|-----------------|----------------|----------------|-------------|-----|
| EASY | 0.37 s | 98.6 | 0.029 | 0.045 | 0.360 | 0 | 40 |
| MODERATE | 0.41 s | 87.8 | 0.189 | 0.234 | 0.538 | 2 | 34 |
| HARD | 1.68 s | 82.3 | 0.264 | 0.305 | 0.654 | 3 | 35 |
| SEVERE | 1.09 s | 88.3 | 0.297 | 0.341 | 0.732 | 3 | 31 |
| ADVERSARIAL | 1.40 s | 94.1 | 0.444 | 0.498 | 0.899 | 6 | 32 |

### 9.3 Key Observations

1. **EASY preset achieves near-perfect tracking**: 0.029° mean error (105 arcseconds), 98.6% retention, zero false locks. This demonstrates the system's fundamental accuracy under nominal conditions.

2. **Graceful degradation**: Mean error increases monotonically from 0.029° (EASY) to 0.444° (ADVERSARIAL), while acquisition time remains under 2 seconds for all presets. The system never catastrophically fails.

3. **Modulation correlation is the primary discriminator**: The phase-robust correlator achieves mean correlation of 0.97–0.98 for the true beacon under light-to-moderate turbulence, dropping to 0.69–0.71 under extreme conditions. Decoy correlations remain below 0.56, providing clear separation.

4. **False-lock events are rare and self-recovering**: Across all presets, false-lock events represent <1% of locked time. Each event self-recovers within 0.3–0.5 seconds via the suspect-floor monitor.

5. **Real-time performance**: Frame rates range from 31–40 fps across all presets, well above the 30 fps minimum for real-time operation.

### 9.4 Comparison with Baseline

The system's 0.029° mean boresight error on EASY represents a >12× improvement over the initial HSV-threshold baseline (0.36°), achieved through:
- Sub-pixel PSF rendering (eliminated 0.036° measurement bias)
- Phase-robust modulation correlator (eliminated 0.50-corr phase failures)
- PD servo tuning (eliminated limit-cycle oscillations)

## 10. AI/ML Integration

### 10.1 Classifier Design

The logistic-regression classifier was chosen for its:
- **Determinism**: No stochastic training variance; baked weights produce identical results across runs.
- **Speed**: Single matrix multiply per candidate (<0.01 ms).
- **Interpretability**: Feature weights directly reveal which visual properties distinguish the beacon.

### 10.2 Training Data

Training data is generated synthetically:
- **Beacon examples**: Gaussian PSFs with varying σ, peak intensity, and additive noise.
- **Distractor examples**: Similar PSFs with different intensity ranges, sizes, and positions.
- **Augmentation**: Gaussian noise injection, intensity scaling, and position jitter.

### 10.3 Feature Engineering

The five features capture complementary information:
- `area_norm`: Beacon has a characteristic PSF area (~22–24 pixels).
- `snr`: Beacon has high SNR (>3) due to concentrated intensity.
- `circularity`: Beacon PSF is nearly circular (>0.85).
- `hue_dist_n`: Beacon hue (warm white) differs from cool-white distractors.
- `peak_normalized`: Intensity normalized to [0,1] range.

## 11. Design Decisions and Trade-offs

### 11.1 Correlation Threshold (0.62)

The modulation lock threshold was tuned through systematic sweeps:
- At 0.55: fast acquisition but false locks increase at HARD/ADVERSARIAL.
- At 0.70: zero false locks but acquisition slows significantly under turbulence.
- **0.62**: optimal trade-off — fast acquisition (0.37–1.40 s) with manageable false-lock rate.

### 11.2 Suspect Floor (0.58)

The continuous-verification floor is set below the true beacon's minimum correlation (0.78) but above the decoy's maximum correlation (~0.56). Under heavy turbulence, the true beacon's correlation can transiently dip to 0.56, approaching the floor. The 30-frame persistence window prevents these transient dips from triggering false drops.

### 11.3 Estimator Alpha (0.35)

The bias-absorption rate α = 0.35 provides a time constant of ~3 frames (50 ms at 60 fps), fast enough to track orbital dynamics while smoothing sensor noise. Higher α (0.5+) introduces jitter; lower α (0.15) lags behind rapid maneuvers.

## 12. Limitations and Future Work

### 12.1 Known Limitations

1. **Blend ambiguity**: When a distractor and the beacon overlap spatially (within one PSF radius), the merged blob's centroid shifts toward the brighter source. Under heavy turbulence (SEVERE/ADVERSARIAL), the beacon's dim-phase intensity can drop below a nearby distractor's, causing transient centroid shifts of 0.3–0.5°.

2. **Modulation degradation under turbulence**: The sign-based correlator's accuracy degrades as turbulence corrupts the intensity waveform. Under ADVERSARIAL conditions (turbulence=85), the mean correlation drops to 0.71, approaching the decoy overlap zone (~0.56).

3. **Single-frame latency**: The 2-frame gimbal latency model is deterministic; real systems may experience variable latency.

### 12.2 Future Improvements

1. **Spatial moment analysis**: Track the blob's second-order moments (width, ellipticity) to distinguish the compact beacon PSF from extended blend blobs.
2. **Adaptive correlation threshold**: Scale the modulation threshold with estimated turbulence strength (measured from image variance).
3. **Multi-hypothesis tracking**: Maintain multiple hypotheses during ambiguous segments and resolve via temporal consistency.
4. **Deep-learning classifier**: Replace the logistic-regression model with a lightweight CNN for richer appearance discrimination.
5. **Extended Kalman filter**: Replace the leaky-absorbed-bias estimator with a proper EKF for better state prediction during coasting.

## 13. Conclusion

This system demonstrates a complete, real-time, AI-augmented beam-pointing solution for mobile FSOC terminals. The key contributions are:

1. **Phase-robust modulation correlator** that eliminates template-misalignment failures while maintaining 0.97+ correlation for the true beacon.
2. **Multi-stage acquisition pipeline** (ML classification + modulation correlation + spatial consistency) that reduces false-lock probability to <0.1% under nominal conditions.
3. **Optimized disturbance engine** running at real-time frame rates through warp-field downsampling and reusable buffers.
4. **PD servo with latency compensation** achieving 0.029° mean boresight error under EASY conditions — well within the coarse-alignment specification for FSOC terminals.

The system achieves 30–40 fps on commodity hardware with no GPU acceleration, making it suitable for edge deployment on embedded platforms.
